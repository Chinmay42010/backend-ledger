// API GUIDE

■ 60-SECOND FLOW

Do it in this order. Token is auto-saved on login/register.

1. AUTH → login (or register). Token fills itself.
2. ACCOUNTS → POST /api/accounts → save the returned _id.
3. TRANSACTIONS → initial-funds (system token) to put money in.
4. TRANSACTIONS → transfer between two accounts (fresh UUID each try).
5. ACCOUNTS → balance/:id to verify. Replay same key → same tx, no double-spend.

■ ENDPOINTS

POST /api/auth/register — public — {name, email, password} → 201 + JWT
POST /api/auth/login — public — {email, password} → 200 + JWT
POST /api/auth/logout — auth — no body → 200, token blacklisted
POST /api/accounts — auth — no body → 201 ACTIVE/INR account
GET /api/accounts — auth — → 200 my accounts
GET /api/accounts/balance/:id — auth, owner — → 200 {accountId, balance}
POST /api/transactions — auth — {fromAccount, toAccount, amount, idempotencyKey} → 200
POST /api/transactions/system/initial-funds — system user — {toAccount, amount, idempotencyKey} → 201

■ ERROR CHEAT-SHEET

401 missing/invalid token → login again.
403 not a system user → initial-funds needs the demo system token.
400 System user account not found → create an account while logged in as system first.
400 Insufficient Balance → fund the sender first.
400 invalid toAccount → check the ID.
Same idempotencyKey twice → original transaction returned, not an error.

■ RULES

Auth header Authorization: Bearer <token> is attached automatically from the token box.
Balances = CREDIT − DEBIT from immutable ledger entries, never stored.
ENTER key inside any card sends that card (same as SEND →).
